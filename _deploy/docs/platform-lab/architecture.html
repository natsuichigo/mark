    Architecture

    Four layers, from the workstation up to images and automation.

    1
    Workstation layerFedora 44 (WSL 2 or native), VS Code, Git, Podman, Python and Go, a Python virtual environment for Ansible
    ↓
    2
    Infrastructure layerTerraform-managed infrastructure and networking definitions (planned)
    ↓
    3
    Platform layerKubernetes on kind, Helm deployments, Traefik ingress, Metrics Server; Argo CD next
    ↓
    4
    Image and automation layerPacker image factory, Ansible, AWX execution environments, Jenkins, n8n, GitHub Actions

    Repository Layout

    The structure is laid out for the whole platform up front, so new components have an obvious home:

    platform-lab/
├── bootstrap/                     # Workstation setup scripts (Fedora on WSL, Ubuntu)
├── kubernetes/
│   ├── kind/platform-lab.yaml     # The Sprint 1 cluster definition
│   ├── helm/  argocd/  ingress/   # Charts, GitOps apps, routing
│   ├── monitoring/  logging/      # Prometheus/Grafana, Loki (later)
│   └── backstage/                 # Deferred
├── images/
│   ├── packer/                    # Packer templates
│   ├── execution-environments/    # Ansible / AWX EEs
│   └── containers/                # OCI image builds
├── infrastructure/
│   ├── terraform/
│   └── networking/
├── automation/
│   ├── ansible/  awx/  jenkins/  n8n/
├── pipelines/                     # Reusable CI/CD templates
├── docs/  scripts/
└── ARCHITECTURE.MD  ROADMAP.md

    The Sprint 1 Cluster

    Deliberately small

    • One kind control-plane node that also runs workloads, with Podman as the node-container provider.
    • Traefik as the ingress controller, installed with Helm into its own namespace.
    • Metrics Server for kubectl top and resource-based autoscaling.
    • Services reached on .localhost names through a loopback-only port-forward: no public DNS, no hosts-file edits, nothing exposed beyond the machine.
