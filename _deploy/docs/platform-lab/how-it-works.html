    How It Works

    The Sprint 1 runbook: from a clean Fedora shell to an app served through ingress.

    1
    Prepare WSLEnable systemd, confirm Podman reports cgroup v2
    ↓
    2
    Create the clusterkind create cluster --config platform-lab.yaml with KIND_EXPERIMENTAL_PROVIDER=podman
    ↓
    3
    Install Traefikhelm upgrade --install traefik traefik/traefik --namespace traefik --create-namespace --wait
    ↓
    4
    Install Metrics ServerUpstream manifest, patched for kind's self-signed kubelet certificates
    ↓
    5
    Deploy a sample apptraefik/whoami in a sprint1 namespace, with a Service and an Ingress
    ↓
    6
    Reach it locallyLoopback port-forward to Traefik, then http://whoami.platform-lab.localhost:8080/

    The Cluster Definition

    kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
name: platform-lab
nodes:
  - role: control-plane

    Routing an App Through Ingress

    kubectl create namespace sprint1
kubectl create deployment whoami --image=traefik/whoami --port=80 -n sprint1
kubectl expose deployment whoami --port=80 --target-port=80 -n sprint1
kubectl create ingress whoami --class=traefik \
  --rule='whoami.platform-lab.localhost/*=whoami:80' -n sprint1

    Names ending in .localhost resolve to loopback, so the app opens in a Windows browser through the WSL port-forward with no DNS record or hosts-file entry.

    Lab-only shortcuts are labelled as such. Metrics Server runs with --kubelet-insecure-tls because kind's kubelet certificates are not signed by a CA it trusts. That is acceptable for a disposable local cluster and is never carried into production. The port-forward stays bound to 127.0.0.1, not 0.0.0.0.

    Practising for CKAD

    The sprint1 namespace doubles as a practice area: scaling, rollouts and rollbacks, probes, ConfigMaps and Secrets, resource requests and limits, scheduling and troubleshooting. Deleting and recreating the namespace resets it between exercises.
