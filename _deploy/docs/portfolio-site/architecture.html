    Architecture

    The repo layout, the two kinds of page, and which files are generated rather than written by hand.

    Two Kinds of Page

    Hub pages: written by hand

    • Home, Projects, Walkthroughs, About, and each case study's index.html.
    • Styled by the shared hub.css; the nav bar is injected by site-chrome.js from a few <meta> tags.
    • Content is a card grid: one card per destination.

    Content pages: generated from Markdown

    • Every docs/<project>/*.html except index.html.
    • MkDocs-Material layout: header, left sidebar, table of contents, previous/next links, footer.
    • Written in Markdown and converted by md_to_page.py. Never edited by hand, because the next build overwrites them.

    Generated vs Written by Hand

    Written by hand
    _deploy/index.htmlprojects/, walkthroughs/, about/docs/<project>/index.htmlassets/*.css, site-chrome.js
    Generated: edit the source, not the output
    docs/<project>/*.html (from _src/*.md)presentations/<slug>/index.html (from a deck plan)
    Do not touch
    _deploy/.nojekylldocs/assets/stylesheets/main.*.min.css

    One Brand File

    Every page, case study and deck reads its colours from assets/theme.css, as CSS custom properties such as --brand-primary and --brand-gradient. Changing the palette there restyles the whole site; no other file hard-codes a brand colour.

    _src/ is published too. It sits inside _deploy/, so the Markdown sources are readable on the live site. That is fine for prose written to be published, but nothing private belongs there.
