    How It Works

    One build, from a workflow run to a published, validated image.

    1
    TriggerA push to dev touching that OS's build files, or a manual run choosing the target (aws, vmware or both) and the environment (dev / prd)
    ↓
    2
    ResolveA small-runner job works out the image version and run parameters
    ↓
    3
    Build (AWS and vSphere in parallel)Large self-hosted runners run Packer; Ansible configures and hardens the image
    ↓
    4
    Validate inlineThe OS's validator runs as the last provisioner before clean-up. Any failure aborts the build
    ↓
    5
    Publish and tidyThe AMI or template is published; old AMIs beyond the retention count are removed
    ↓
    6
    SummariseA separate job merges both platforms' results into one run summary, even on failure

    Validation Inside the Build

    Each OS has a validator in tests/: validate-rhel-image.sh, validate-al2023-image.sh and validate-windows-image.ps1. They print records in a shared vocabulary that the summary action understands:

    Record Example
    Section header ━━━ Operating System ━━━ or --- Operating System ---
    Check PASS : SSM agent installed, with FAIL, WARN, SKIP or INFO
    Benchmark 🔧 Disk write speed: …
    Summary A closing block with Passed:, Failed: and Warnings: counts

    One summary parser handles every OS family, so adding an OS means emitting the same records, not writing a new parser.

    Credentials and Security

    • AWS access through OIDC. Workflows assume an IAM role; there are no stored AWS access keys.
    • The build account is ephemeral. Its password passes through EC2 UserData, so it is treated as disposable and rotated freely.
    • Windows on AWS never ships the build password. The final provisioner replaces it with a bootstrap password, if one is configured, or with a random 32-character password that is never recorded. Instances are reached through SSM Session Manager.
    • Nothing sensitive is committed. Certificates, keys and passwords come in as PKR_VAR_* environment variables or secrets.

    Building Locally

    Validation needs no cloud or vCenter connection:

    packer init builds/aws/linux/rhel/8.10
packer fmt -check -recursive builds/
packer validate \
  -var-file=builds/aws/common.pkrvars.hcl \
  -var-file=builds/aws/linux/rhel/8.10/linux-rhel.pkrvars.hcl \
  -var image_version=20260101-test -var ami_name=rhel-8-10-test \
  builds/aws/linux/rhel/8.10
