    Architecture

    Three EE definitions, three workflows, and the composite actions they share.

    The Lifecycle

    ci-base-latest  (core 2.18 / py3.13) ──┐
                                       ├──> ci-dev ──> dev repo  (vX, core216-vX)
ci-base-compat  (core 2.16 / py3.12) ──┘                    │
                                                            │  manual + approval
                                                            ▼
                                          ee-promote-prod ──> prod repo (same tags)

    Repository Layout

    ansible-execution-image-pipeline/
├── execution-environments/
│   ├── base-core-2.18/            # definition, validation.yml, latest-target-test.yml
│   ├── base-core-2.16/            # definition, validation.yml, compat-target-test.yml
│   └── derived/                   # definition template (__EE_BASE_IMAGE__), validation.yml
└── .github/
    ├── workflows/
    │   ├── ee-build-dev.yml       # push to dev / manual: build + test + push to dev
    │   ├── ee-tech-preview.yml    # manual: derived EE from a chosen base tag
    │   └── ee-promote-prod.yml    # manual + approval: copy tested tags to prod
    ├── actions/ee_build/
    │   ├── build/pipelines/       # ci-base-latest, ci-base-compat, ci-dev, prod-promote
    │   ├── build/tasks/           # resolve-image-tags, build-image, build-derived-ee
    │   ├── setup/                 # toolchain, registry login
    │   ├── verify/                # validate-image, target-test
    │   ├── publish/               # push-image-tags
    │   └── summary/               # write-run-summary
    └── dependabot.yml             # weekly GitHub Actions updates

    Three Repositories, Three Stages

    Base and dev: built and tested automatically

    • A push to dev builds both base EEs, validates them, runs the target tests, then builds a derived EE on each.
    • Images go to the base and dev repositories with immutable version and SHA tags.
    • A non-production AAP points at the dev images for soak testing.

    Prod: promoted, never rebuilt

    • ee-promote-prod.yml runs by hand and waits for a reviewer on the production environment.
    • It copies the chosen dev tags into the prod repository under the same tags.
    • With push_image off it is a dry run: it verifies the images and writes the promotion plan without pushing.

    Tagging Convention

    Tag type Core 2.18 Core 2.16 compat
    Immutable version vYYYYMMDD-NNN core216-vYYYYMMDD-NNN
    Immutable SHA sha-xxxxxxx core216-sha-xxxxxxx
    Mutable latest, stable, tech-preview core216- + the same

    Production job templates in AAP point at an immutable tag or at stable, never at latest.
